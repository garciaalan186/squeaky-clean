# Changelog

All notable changes to Squeaky Clean will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **The creational and structural families are authored once and composed per language** — all 5 creational patterns (`AbstractFactory`, `Builder`, `FactoryMethod`, `Prototype`, `Singleton`) and all 7 structural patterns (`Adapter`, `Bridge`, `Composite`, `Decorator`, `Facade`, `Flyweight`, `Proxy`) are now written as one cross-language template each, at `squeaky_clean/interface/agent_specs/emitters/_shared/creational/<Pattern>Emitter.md` and `emitters/_shared/structural/<Pattern>Emitter.md`, composed at emission time by `ComposeEmitterSpec` with the per-language profile at `emitters/_shared/profiles/<language>.md` (profiles ship for `python`, `javascript`, `typescript` and `java`); their per-language spec files are gone — 48 of them, 12 patterns across the four languages — and `emitters/<language>/creational/` and `emitters/<language>/structural/` now hold no pattern specs. That puts 23 of the 34 catalog patterns on shared templates — 11 behavioral, 5 creational, 7 structural — and leaves the 11 DDD/Clean patterns as the only family still shipping one complete spec file per language, 44 files across the four languages, where the split was previously the inverse: 11 shared and 23 per-language, 92 files. Adding a target language accordingly means one profile covering all 23 shared-template patterns, plus a per-language spec file for each of the remaining 11. The drift guards — the Java §Notation `float` → `double` type-fidelity rule and the sibling-capability-fidelity rule among them — are asserted once per pattern against the composed template + profile rather than against four file copies, now parameterized over all 23 shared-template patterns rather than 11. Unchanged: the catalog is still 34 patterns — 5 creational, 7 structural, 11 behavioral, 11 DDD/Clean — with `SimpleClass` as the escape hatch; the four supported languages; the template grammar (`{{profile:<block_name>}}`, the line-based `{{#lang:…}}` … `{{/lang}}` block and its comma lists) and the shipped profile block names, no new block having been needed; fallback resolution, the shared template used when one exists and otherwise the per-language file loaded unchanged, a shared template with no matching language profile still an authoring error that raises loudly; and the shape of the generated code, every per-language idiom rule the deleted files carried surviving in the templates — Java's static-holder `Singleton`, Java's private copy constructor for `Prototype`, TypeScript's private constructor plus `getInstance()`, JavaScript's frozen module-level singleton, and so on. The Tier C infrastructure emitters and the security emitters stay per-language and are untouched. Documented in `docs/architecture.md`, `docs/extending.md` and `CONTRIBUTING.md`.
- **Mirror tests for ten grandfathered modules** — the grandfathered-debt baseline at `tests/self_conformance/baseline.json` shrank by ten entries: the missing-mirror-test exemptions for `application/generation/integration/manifests/build_manifest_helpers.py`, `build_manifest_registry.py` and `build_manifest_templates.py`, for `application/generation/integration/wiring_construction.py` and `wiring_walker.py`, and for `application/generation/recovery/decomposition/clean_split_factory.py`, `domain_scc_finder.py`, `module_assigner.py`, `module_assignment.py` and `module_exports_builder.py` are gone, their mirror tests having landed.
- **Emitter specs can be authored once and composed per language** — a pattern emitter may now be written as a single cross-language template at `squeaky_clean/interface/agent_specs/emitters/_shared/<category>/<Pattern>Emitter.md`, composed at emission time with a per-language profile at `emitters/_shared/profiles/<language>.md` (profiles ship for `python`, `javascript`, `typescript` and `java`), instead of as four near-identical per-language files kept in step by hand. `ComposeEmitterSpec` (`squeaky_clean/application/generation/emission/composition/compose_emitter_spec.py`) resolves by fallback: the shared template when one exists for the pattern, otherwise the per-language file loaded unchanged — so a pattern not yet cut over behaves exactly as before — and a shared template with no matching language profile is an authoring error that raises loudly rather than silently degrading. The template grammar is deliberately flat, blocks not nesting: `{{profile:<block_name>}}` pulls in a named delta block from the composing language's profile, an unknown reference left literal as the shared-spec composer already does; a line-based `{{#lang:java}}` … `{{/lang}}` block, whose opener accepts a comma list (`{{#lang:python,typescript}}`), keeps its inner lines only for the listed languages, the marker lines themselves never surviving and lines outside any block always surviving; and the existing language-toolkit placeholders are substituted afterwards, so a composed spec carries no unresolved `{{…}}`. A profile is markdown in which every `## <block_name>` heading opens a named block running to the next heading (`EmitterProfile`), the shipped block names being `language_name`, `fence_tag`, `input_suffix`, `file_preamble`, `abstract_idiom`, `concrete_idiom`, `style_rule`, `arg_note`, `import_rule`, `language_rules`, `error_rule`, `shadowing_rule`, `fields_rule`, `sibling_fields_rule`, `collection_default_rule`, `floor_expr`, `extra_constraints` and `polymorphism_note`; a block may legitimately be empty. The whole behavioral family is cut over: all 11 patterns — `ChainOfResponsibility`, `Command`, `Interpreter`, `Iterator`, `Mediator`, `Memento`, `Observer`, `State`, `Strategy`, `TemplateMethod` and `Visitor` — are authored as one shared template each and composed with the four profiles, their per-language spec files gone and `emitters/<language>/behavioral/` holding no pattern specs, while the remaining 23 catalog patterns (5 creational, 7 structural, 11 ddd_clean) still resolve to their per-language files, 92 of them across the four languages. The drift guards are asserted once per pattern against the composed template + profile rather than against four file copies — the Java §Notation `float` → `double` type-fidelity rule among them — parameterized over every cut-over pattern. Adding a target language accordingly means one profile covering all 11 behavioral patterns, plus a per-language spec file for each of the remaining 23. Unchanged: the catalog is still 34 patterns with `SimpleClass` as the escape hatch, the four supported languages, the spec lookup key a pattern maps to, and the per-language specs of every pattern outside the behavioral family. Documented in `docs/architecture.md`, `docs/extending.md` and `CONTRIBUTING.md`.
- **`--micro-patterns` — narrow the micro-eval matrix to one pattern family** — `--micro-patterns <prefix>[,<prefix>...]` modifies `--micro-evals` rather than being a top-level command of its own, and restricts the matrix to the squib fixtures in `eval/squib_fixtures/` whose filename stem starts with one of the comma-separated prefixes; the default is empty, which runs every fixture exactly as before. The match is on the stem, so `--micro-patterns state` takes `state.squib` and `state_depends_shape.squib` together, and `squeaky --micro-evals --micro-patterns strategy,visitor` iterates on one pattern's emitters without paying for the full fixture × language matrix. Unchanged: the accepted top-level commands, the per-language compile gates, the report format and the printed one-line result. Documented in `docs/architecture.md`, `BENCHMARK_METHODOLOGY.md`, `README.md` and `CONTRIBUTING.md`.
- **`TechSpecResolutionError` — technology-spec resolution reports why every source failed** — active only under `--infra=auto`. The resolution order is unchanged (bundled snapshot → fresh cache → MCP → web fetch → a stale-tolerant cache entry inside the TTL × 1.5 grace window → fail), but every failed source now emits a structured JSON run-log event carrying its reason, and when nothing resolves the run raises `TechSpecResolutionError` (`squeaky_clean/domain/interfaces/tech_spec_resolver.py`) — a subclass of the existing `TechSpecUnresolvableError`, so every `except TechSpecUnresolvableError` site keeps working — carrying a `reasons` tuple with one entry per source it tried and why that source failed. The new event kinds are `techspec_fs_miss`; `techspec_snapshot_rejected` (a bundled snapshot exists but is unreadable, is not a JSON object, fails schema validation, or is rejected by the builder — path and reason logged); `techspec_cache_rejected` (a cache entry is unreadable, is not a JSON object, has a mismatched `schema_version`, or has bad timestamps); `techspec_source_failed` with the source (`fresh-cache`, `mcp`, `web` or `stale-cache`) and the reason; `techspec_stale_cache_used` when a grace-window entry is served through an outage; and the terminal `techspec_unresolvable` carrying every reason. The tech-spec stage logs `tech_spec_resolution_failed` with all reasons and then fails the run, so resolution never degrades silently. Resolution outcomes are now an explicit union in the domain (`squeaky_clean/domain/value_objects/`): the success variant is `TechSpec` itself, alongside `TechSpecFetchFailed(reason)` and `TechSpecPoisoned(reason)`, the sanitizer rejection kept deliberately distinct from an availability failure because a poisoned document is a security signal that must never be retried around while a fetch failure legitimately may be; `None` survives inside the resolver chain only where it means "source not applicable / clean cache miss", never "an error happened". Unchanged: the resolution order, the error message itself — `no TechSpec for (<category>, <technology>, <version>); add a bundled snapshot at eval/tech_specs/<category>/<technology>/<version>.json` — and the silence of a missing file, an absent allowlist entry or a clean cache miss. Documented in `docs/infrastructure_layer_design.md`, `docs/architecture.md` and `docs/extending.md`.
- **`ManifestWriteError` — a failed build-manifest write raises instead of returning `None`** — the generators for `package.json`, `requirements.txt`, `tsconfig.json`, `pom.xml`, `go.mod` and `Cargo.toml` now raise `ManifestWriteError` (`squeaky_clean/application/generation/integration/manifests/manifest_write_error.py`, a `RuntimeError` and deliberately not an `OSError`) when a write fails, so `None` from a generator means only "not applicable for this language / spec set" and never "something went wrong". `ManifestEmitter` catches `(OSError, ManifestWriteError)` and logs a `*_emit_failed` event carrying the reason — manifest emission stays best-effort, but is never silent. Unchanged: which manifests are generated for which language, and their contents. Documented in `docs/architecture.md`.
- **Self-conformance gains a no-silent-swallow test** — `tests/self_conformance/test_no_silent_swallow.py` mechanically bans `return None`, a bare `return` and a bare `pass` inside an `except` block across `squeaky_clean/infrastructure/techspec/`, `squeaky_clean/application/generation/techspec/` and `squeaky_clean/application/generation/integration/manifests/`, so the no-silent-swallow contract cannot regress. It is a plain unit test local to those directories, deliberately not a conformance-scan rule. The grandfathered-debt baseline at `tests/self_conformance/baseline.json` also shrank by two entries — the missing-mirror-test exemptions for `techspec_cache_metadata.py` and `squeaky_clean_cli.py` are gone, a file split having cleared a granularity exemption on the former. Unchanged: `None` remains a legal return value in those modules, but only on a path that means "not applicable / clean miss". Documented in `CONTRIBUTING.md`.
- **`GitInfo` and `ToolchainInfo` — provenance ports behind the run manifest** — two new domain ports at `squeaky_clean/domain/interfaces/provenance/`: `GitInfo.head_sha() -> str` returns the framework checkout's HEAD SHA, or `"unknown"` when the checkout state cannot be determined, and `ToolchainInfo.versions() -> dict[str, str]` returns tool → first version line, with `"absent"` for any tool not on `PATH`. The subprocess implementations are infrastructure adapters — `GitInfoAdapter` and `ToolchainProbeAdapter` at `squeaky_clean/infrastructure/observability/` — so every shell-out sits behind a port and the application layer is subprocess-free. `RunManifest` takes both by injection and is itself supplied through `RunEvalDependencies.run_manifest`, wired in the composition root; left unwired it degrades to `framework_sha: "unknown"` and an empty `toolchains` map rather than failing a run, because losing provenance must never cost a result. Unchanged: what `manifest.json` records, the six probed tools, and the five-second per-tool timeout. Documented in `docs/architecture.md`.
- **`atomic_write_text` — crash-safe writes for framework artifacts** — `squeaky_clean/application/shared/io/atomic_write.py` writes to a sibling temp file in the target directory and renames it into place, so a reader sees either the old contents or the new ones and never a partial. Every framework-internal artifact now goes through it — run summaries, `CHECKPOINT.json`, the HTML dashboards, `architecture.notation`, `LATENCY_PERCENTILES.md` and the violation reports — because a bare `Path.write_text` truncates the target before writing, so a crash or a budget exit mid-write left a half-written file that a later `--resume` parsed as corrupt. Extracted from `CheckpointWriter`, the one site that already did this. Unchanged: artifacts belonging to the generated project are still written through the `ProjectFileSystem` port, and the file contents themselves are identical. Documented in `docs/architecture.md`.
- **`ClassRole` — the polymorphic role of a Squib class, named once** — a new value object at `squeaky_clean/domain/value_objects/class_role.py` with members `ABSTRACT`, `CONCRETE` and `PLAIN`, derived from a `ClassSpec`'s `implements:` / `concretes:` fields and exposed as `ClassSpec.role()`: `ABSTRACT` when the class declares `concretes:` (emitters render it as an interface), `CONCRETE` when it declares an `implements:` target, `PLAIN` otherwise. Unchanged: the two equivalent Squib shapes for a polymorphic split, the `PolymorphicRoleNormalizer` pass that reconciles them, and the emitted code. Documented in `docs/squib.md`.
- **Self-conformance ratchet gains `FsPortBypass` and `ImpureConstruction`** — two AST scanners at `tests/self_conformance/di_conformance_rules.py`, wired into `conformance_scan.py`. `FsPortBypass` flags a raw `.write_text` / `.write_bytes` call anywhere under `application/generation/**` (generated-project artifacts belong to the `ProjectFileSystem` port) or `application/evaluation/**` (framework artifacts belong to `atomic_write_text`, an ordinary function call rather than an attribute write, so calls to it pass); `mkdir`, `exists` and `open` are deliberately out of scope, the rule being about writes. `ImpureConstruction` flags the construction of an I/O-touching class — `JSONLogger`, `LocalFileSystem`, `ClaudeCLIGateway`, `AnthropicSDKGateway`, `CachingLLMGateway`, `ContentAddressedCache`, `LoadAgentSpec` — anywhere under `application/**`, whether at module top level, in an `__init__` or in a method body; those arrive by injection from the composition root. Like `ReflectionBan`, both are framework-only: part of the self-conformance gate, not of the `validate_architecture` pass that runs over generated projects. Documented in `CONTRIBUTING.md` and `docs/architecture.md`.
- **Self-conformance ratchet bans f-string-driven reflection** — the framework's own source is now additionally scanned for `setattr` / `getattr` called with a dynamically built attribute name, banned framework-wide and reported under the key prefix `ReflectionBan` (`tests/self_conformance/conformance_scan.py`). Dynamic attribute access defeats `mypy --strict` at exactly the seam where a renamed field should fail loudly, so the rule is framework-only: it is part of the self-conformance gate, not of the `validate_architecture` pass that runs over generated projects. The grandfathered-debt baseline at `tests/self_conformance/baseline.json` also shrank by one entry — the sweep CLI's file-length exemption is gone. Documented in `CONTRIBUTING.md` and `docs/architecture.md`.
- **`--architect-mode {patterned,free}` — an ablation control over the pattern vocabulary** — `patterned` is the default and is today's behaviour unchanged: the RequirementCompiler annotates every class with the GoF/DDD pattern it plays, and each class routes to that pattern's dedicated emitter. Under `free` every class is annotated `SimpleClass` instead, so each routes to the escape-hatch emitter, while the module decomposition, the layer assignment, the class granularity and the invariants come out exactly as they do under `patterned` — only the pattern annotation is fixed. The two arms therefore differ in exactly one variable, which is what makes the difference between them attributable: run the same problem both ways at N ≥ 3 and the delta in `tests_pass`, functional pass rate, architecture violations and cost is the measured contribution of the pattern vocabulary itself, rather than an assumption about it. Carried on `RunConfig.architect_mode` into `DesignArchitecture` (`squeaky_clean/application/generation/architecture/design_architecture.py`). Documented in `docs/architecture.md` and `BENCHMARK_METHODOLOGY.md`.
- **`notation_novelty` — an observational count of architect Squib shapes the fixture corpus has never seen** — `EvalMetrics` gains `notation_novelty` (integer, default 0), reported in every run's `eval_report.json` alongside the reliability metrics; it never gates and is not part of the regression gate. A *shape* is a class's pattern name plus which of `fields`, `methods`, `depends`, `concretes`, `implements` and `invariants` it declares, and "known" is defined by the `.squib` fixtures in `eval/squib_fixtures/` — every shape appearing in that corpus is a tested construction. Every run writes `notation_novelty.json` into the problem-set directory beside the emitted notation, shaped `{"count": <n>, "novel": ["<Pattern>:<six flag bits>", …]}` with the list sorted and the bits ordered `fields`, `methods`, `depends`, `concretes`, `implements`, `invariants`. When the count is non-zero the raw notation is also copied into `<results-root>/notation-triage/`, named after the run and problem-set directories, so a new architect shape is adopted into the fixture corpus deliberately instead of being met first in production as a downstream contract break; the harvest is best-effort, so if it cannot be written the run is unaffected and the sidecar still records the count. Notation that fails to parse reports zero and writes no sidecar. Implementation at `squeaky_clean/application/evaluation/eval/run/notation_novelty_reporter.py` (`NotationNoveltyReporter`) and `squeaky_clean/application/generation/notation/notation_shape_classifier.py` (`NotationShapeClassifier`). Documented in `docs/squib.md` and `docs/architecture.md`.
- **Run manifests record the toolchain versions they ran under** — `manifest.json` gains a `toolchains` entry alongside the per-tier model identifiers, the framework SHA, the spec-library version and hashes, and the replicate id. It records the first version line reported by `node`, `npm`, `javac`, `mvn`, `go` and `cargo`, and `absent` for any tool not on `PATH` — also `absent` when the probe errors or exceeds its five-second timeout. Scores depend on these: a Node major version, or a JDK that rejects language features a newer one accepts, changes results, so a manifest can now attribute a score to the environment that produced it. Implementation at `squeaky_clean/infrastructure/observability/toolchain_probe_adapter.py`, read by `RunManifest` through the `ToolchainInfo` port.
- **`--replay-only` — serve every LLM call from the response cache** — the flag modifies a normal run (`--problem P0 --replay-only`) rather than being a top-level command of its own, and swaps the live gateway out of the chain for `CacheMissRaiser` (`squeaky_clean/infrastructure/llm/cache_miss_raiser.py`), an `LLMGateway` implementation that raises on every call. Any prompt not already in the content-addressed response cache therefore fails loudly with `ReplayCacheMissError` (`squeaky_clean/infrastructure/llm/replay_cache_miss_error.py`, a `RuntimeError` subclass) instead of reaching the API; the message carries the model, the cache-key prefix and the head of the prompt, so the drifted prompt is identifiable from the error alone. Everything outside the LLM seam runs for real — spec parsing, model routing, pattern emission, integration, the generated project's test suite and scoring. A replay-only run costs $0 and needs no API key.
- **`SQUEAKY_CACHE_DIR` — override the response cache directory** — read in `DependencyBuilder` when wiring `CachingLLMGateway`, so a run can be pointed at a committed replay bundle instead of the ambient cache. Unchanged: the default remains `meta-evaluation-results/cache/` next to the framework checkout, anchored relative to the checkout so it still runs from any clone.
- **$0 end-to-end eval replay in CI** — continuous integration now replays benchmark problem P0 from a small cache bundle committed at `tests/ci_replay_cache/`, invoking the CLI as `python -m squeaky_clean.interface.cli --problem P0 --replay-only` with `SQUEAKY_CACHE_DIR` pointed at the bundle. The full pipeline runs — only the LLM calls are served from disk — so the gate covers what the unit suite cannot: prompt or agent-spec drift surfaces as a `ReplayCacheMissError`, and a harness regression surfaces as a changed score. No API key is needed or used by CI. The step runs alongside the existing unit test suite step. Editing an agent spec or any prompt turns this gate red until the committed bundle is refreshed.
- **`--micro-evals` — the pattern × language micro-eval matrix** — for every squib fixture in `eval/squib_fixtures/` (`*.squib` — every file in the directory, which is a superset of the routing fixtures listed in `manifest.json`), the command emits that fixture module's classes through the real model routing and the real pattern emitters, then compiles the result, once per target language (Python, Java, TypeScript). It is the middle tier between unit tests (which stop at the LLM seam) and full benchmark problems: a handful of LLM calls plus one compiler invocation verifies that a pattern's emitters produce COMPILING code in a language. All sibling classes of the fixture module are emitted together, so cross-class contracts (`implements`/`extends`) are exercised, not just single-file syntax. Every fixture is self-contained: each type its focal class references — parameter, return and field types, and the entries of `concretes:` — is declared as a sibling and emitted alongside the focal class, so a cell's compile never depends on a type the module never declared; `domain_event.squib` additionally carries a class-level `invariants:` entry, exercising `invariants:` on a DomainEvent in this path. Each cell is isolated — a failure or exception in one cell fails only that cell, and a language with no compiler or implementer registered fails the cell loudly rather than being silently skipped. Cells are written under `<run-dir>/micro-evals/<pattern>-<language>/`; `micro_eval_report.md` and `micro_eval_report.json` land in the run directory. The Markdown report is a pattern × language pass matrix (✅ / ❌ with the compile-error count, — where a cell has no adapter) with header counts of cells / passed / failed / total cost, plus a Failures section listing `pattern/language`, the error count and a compiler-output excerpt. The command prints `[squeaky] micro-evals: <passed>/<total> cells passed, $<cost> — <report path>` and exits. `--micro-evals` joins the accepted top-level commands: the CLI requires exactly one of `--problem`, `--problems`, `--sweep`, `--problem-file`, `--recover-from`, `--triage`, `--refactor`, `--squib-file`, `--rebuild-dashboard`, `--micro-evals`, or `--resume`.
- **Per-language compile gates for the micro-eval** — Java compiles with the JDK's `javac` directly against every `.java` file in the cell, needing no Maven and no `pom.xml` and running an order of magnitude faster than `mvn` (60-second timeout, class output under `_out/`); Python has no ahead-of-time compile step, so the gate parses every `.py` file, which still catches truncated emissions, stray prose and malformed definitions; TypeScript uses the existing TypeScript compiler with `tsconfig.json` (ES2022, nodenext modules, strict, noEmit, esModuleInterop, skipLibCheck, `include: ["src/**/*.ts"]`) and `package.json` (`{"type": "module"}`) scaffolded into each cell, mirroring what the integration bootstrap generates for full runs. Java micro-eval cells promote the ICP tier to the manager model, because the small model misses Java contracts often enough to matter — mirroring the per-problem recipe.
- **Regression gate against calibrated golden baselines** — every sweep now judges each problem's result against that problem's stored golden baseline and writes a verdict per problem into the sweep summary under a `## Regression Gate (vs routing-stamped goldens)` section: `<pid>: no golden (uncalibrated)` (no baseline; never gates), `<pid>: not comparable (routing changed since calibration)` (the current tier→model routing differs from the calibration routing — a model change, not a tool regression, and deliberately not gating), `<pid>: OK (tests <current> vs golden <mean>±<sigma>)`, or `<pid>: REGRESSION <metric> <current> vs <mean>±<sigma> (drop <n>σ)` for a drop of 2 sigma or more below the baseline mean. When any metric trips, `regressions.json` is written into the run directory. Each verdict is also emitted as a `regression_gate` log event. A baseline attaches to a problem spec as the optional field `golden_metrics: GoldenMetrics | None`, where `None` means uncalibrated and never gates; `GoldenMetrics` is a frozen value object carrying `replicates`, the mean and stddev of `tests_pass`, `functional_pass`, `security_pass` and `cost_usd`, `model_routing` (a tuple of `"<tier>=<model>"` entries for architect / manager / icp / fixer, recording what the calibration ran under) and `calibrated_run` (the run directory name). Unchanged: wall-clock and cache fields are not calibrated and do not gate.
- **Published calibrated baselines for P0 and P2** — N=3 replicates, seeds 0–2, dated 2026-07-30, calibrated under routing architect=`claude-sonnet-5`, manager=`claude-sonnet-5`, fixer=`claude-sonnet-5`, icp=`claude-haiku-4-5-20251001`. P0 Calculator: tests pass 1.00 ± 0.00, functional 1.00 ± 0.00, security 0.00 ± 0.00 (not measured), cost $0.0187 ± 0.0113, calibrated run `meta-evaluation_457_20260730-164556`. P2 E-Commerce Cart: tests pass 1.00 ± 0.00, functional 1.00 ± 0.00, security 0.00 ± 0.00 (not measured), cost $0.0482 ± 0.0436, calibrated runs 454–456 with calibration stamp `meta-evaluation_454_20260730-163813`. P1 and P3 carry no golden baselines and remain uncalibrated. Published in `BENCHMARK_METHODOLOGY.md`.
- **Squib polymorphic role inference** — `PolymorphicRoleNormalizer` (`squeaky_clean/application/generation/emission/polymorphic_role_normalizer.py`) runs inside `AssignPatterns.assign_all` before emitter dispatch and derives the abstract-vs-concrete participant roles the architect left implicit, across the seven pattern families whose participants split that way: Strategy, State, Visitor, Observer, Command, TemplateMethod, ChainOfResponsibility. Two Squib shapes are now equivalent — the canonical one where the abstract declares `concretes: [A, B]` and each concrete declares `implements: <Abstract>`, and the peer shape where each concrete only declares `depends: [<Abstract>]` and the abstract declares no `concretes:`. A `depends:` edge between two classes carrying the same polymorphic pattern name is read as concrete → abstract: those names are appended to the abstract's `concretes:` and `implements:` is stamped on each concrete, merged with anything already declared without duplicates. Emitter specs key interface-vs-concrete emission on `concretes:` / `implements:`, so the peer shape previously emitted a concrete abstract participant and a Java "interface expected here" compile error. Pure function — no LLM call, no added cost. Unchanged: edges between classes of different patterns (an Entity depending on a Strategy) and edges between non-polymorphic patterns (Entity → Entity) remain ordinary collaborators. Documented in `docs/squib.md`.
- **Complete pattern emitter catalog** — all 34 GoF + DDD/Clean patterns now have a dedicated agent spec in every supported language (Python, TypeScript, JavaScript, Java): 5 creational, 7 structural, 11 behavioral, 11 ddd_clean. 92 specs under `squeaky_clean/interface/agent_specs/emitters/<lang>/<category>/` for the creational, structural and ddd_clean families, plus the 11 behavioral cross-language templates and the four language profiles under `emitters/_shared/`. Each is written to its own language's idioms rather than transliterated from the Python spec.
- **Pattern-rich benchmark problems P6–P9** — four Python problems in the built-in registry (`squeaky_clean/interface/cli/problem_resolver.py`), selectable by id via `--problem` / `--problems`: `P6 stock_monitor` (Observer — subscribers are notified on price update, unsubscribed investors are not), `P7 order_lifecycle` (State — Pending → Paid → Shipped → Delivered, each state permitting only its one valid forward transition), `P8 text_editor` (Command + Memento — insert/delete commands snapshot the buffer for single-level undo), `P9 drawing_canvas` (Composite + Visitor — nested shape groups traversed by an area visitor). The spec directory `squeaky_clean/interface/agent_specs/icps/` is now `.../emitters/`, and every `<Pattern>ICP.md` is now `<Pattern>Emitter.md`, so a resolved spec path reads `<lang>/<category>/<Pattern>Emitter` (e.g. `emitters/python/ddd_clean/EntityEmitter.md`, `emitters/typescript/behavioral/ObserverEmitter.md`). Existing manifests must be updated. The bundled worked example moved to `eval/custom_patterns/specs/emitters/python/custom/EventSourcedAggregateEmitter.md`, referenced from `eval/custom_patterns/example_event_sourced_aggregate.json`. Because the bundled catalog now covers all 34 patterns in all four languages, the hook is only needed for patterns outside that catalog.

### Fixed

- **Architect Squib emissions truncated mid-structure on multi-pattern briefs** — `DesignArchitecture` (`squeaky_clean/application/generation/architecture/design_architecture.py`) now requests `max_tokens=16384` on the architect call instead of inheriting the gateway's 4096 default. Root cause: the Sonnet architect's adaptive thinking shares the output-token budget with the Squib text, so on a multi-pattern brief like `P11 notification_middleware` the thinking alone consumed the whole default and the Squib text either truncated mid-structure with unbalanced braces or never started — an exhausted budget rather than the early stop it looked like. A probe measured 4466 output tokens needed to reach a clean `end_turn`. `max_tokens` is a capacity knob billed only on actual use, so the headroom costs nothing unless it is consumed, and it stays excluded from the cache key. P11's recalibration then ran 3 of 3 replicates with zero architect failures.
- **A failed replicate no longer aborts the whole calibration** — `--replicates N` isolates per-replicate failures: the failure is recorded and excluded from the aggregated statistics while the surviving replicates still produce a summary. `ReplicateReport` gains a `failures` tuple; `replicate_summary.json` gains a `failures` array of strings shaped `"replicate <N>: <ErrorType>: <message>"`, and `replicate_summary.md` renders a line reporting how many replicates failed and were excluded from the stats, listing them. Two infrastructure signals still abort the whole calibration deliberately — `BudgetExceededError` (the cost cap) and `ReplayCacheMissError` (a replay-only cache miss) — since neither is a benchmark result. When no replicate produces a result there is nothing to aggregate, and the run raises `ReplicateCalibrationError` (`squeaky_clean/interface/cli/replicates/replicate_calibration_error.py`, a `RuntimeError` subclass) naming the problem id and every failure.
- **Generated Java pinned to a JDK-neutral syntax level** — every Java emitter spec now requires a plain `public final class` with explicit private final fields, a constructor and getters; `record`, `sealed` and `var` are forbidden. A generated Java project therefore compiles on any JDK ≥ 11 rather than on whichever JDK the emitter happened to write for. Unchanged: the toolchain the compile gate itself runs on — JDK 21, Temurin in CI, Maven 3.8+.
- **Invented sibling members in generated Java** — every Java pattern emitter spec, across `behavioral/`, `structural/`, `creational/` and `ddd_clean/` under `squeaky_clean/interface/agent_specs/emitters/java/`, now carries a sibling-capability-fidelity constraint: the emitter may call only the methods and fields the sibling ClassSpec block actually declares. No invented getters (`getUsername()` when the sibling declares `getName()`), and no operators applied to declared class types — use the declared method, e.g. `total = total.add(x)` rather than `total + x`. The §Notation `float` → `double` type-fidelity rule is extended from the behavioral family to all four Java pattern families, and the spec-language test that enforces it now parametrizes over all four.
- **Empty model responses were cached and replayed forever** — `CachingLLMGateway` now skips the store when a response's content is empty or whitespace-only, in addition to the existing skip for a timed-out response. Previously a failed model call — an architect emission that came back blank, say — was written to the content-addressed cache and served from it on every subsequent run of the same prompt, so one transient failure turned into a permanent empty result for that prompt, in cached and `--replay-only` runs alike. Such a call is now retried live instead.
- **Sweeps dropped the run configuration** — `--problems` and `--sweep` built their dependencies without the `RunConfig`, so run-level flags never reached the gateway and applied to no problem in the sweep. The sweep path now carries the run config through, so `--replay-only` — and every other gateway-level flag — applies to every problem in the sweep.
- **A replay cache miss inside a sweep is no longer recorded as a problem failure** — `ReplayCacheMissError` now propagates out of the per-problem handler and aborts the whole sweep, after emitting a `replay_cache_miss` log event naming the problem. A miss is an infrastructure signal — prompt drift or a stale bundle — not a benchmark result, so it can never be scored as one problem's failure and reported as a green sweep. Matches how `BudgetExceededError` already aborts.
- **Lossy-conversion compile errors in generated Java** — every Java behavioral emitter spec (`ChainOfResponsibilityEmitter`, `CommandEmitter`, `InterpreterEmitter`, `IteratorEmitter`, `MediatorEmitter`, `MementoEmitter`, `ObserverEmitter`, `StateEmitter`, `StrategyEmitter`, `TemplateMethodEmitter`, `VisitorEmitter` under `squeaky_clean/interface/agent_specs/emitters/java/behavioral/`) now carries the Squib → Java type-fidelity mapping as its first constraint: `str`→`String`, `int`→`int`, `float`→`double` (never Java `float` — mixing `float` fields with `double` arithmetic is itself a lossy-conversion error), `bool`→`boolean`, `None`→`void`, `Type[]`→`List<Type>`, `dict`→`Map<K, V>`, applied identically to fields, parameters and return types. Unchanged: the Squib type-vocabulary table in `docs/squib.md`, which already published this mapping — the specs now enforce it.
- **TS2540 compile errors in generated TypeScript** — the TypeScript `EntityEmitter` and `AggregateEmitter` specs now state that ValueObject sibling fields are `readonly` / frozen and must never be assigned to or incremented (`item.quantity += n`, `item.price = p`), since any assignment to them is a TS2540 error. To change one, the emitter constructs a replacement: remove the old instance from the collection and push a newly built one carrying the updated values.
- **Generated TypeScript projects typechecked against an unpinned compiler** — `package_json_generator.py` (`squeaky_clean/application/generation/integration/manifests/`) wrote `typescript ^5.4.0`, `ts-jest ^29.1.0` and `@types/node ^20.0.0` into the generated `package.json` only when at least one infrastructure TechSpec declared a TypeScript npm package, so a plain TypeScript problem with no infrastructure dependencies got `devDependencies` holding nothing but `jest ^29.7.0` and ran `npx tsc --noEmit` against whatever TypeScript version happened to resolve on the machine that day. The pin is now driven by the problem's `target_language`: any problem targeting `typescript` gets the pinned toolchain, with or without TechSpecs. Unchanged: `jest ^29.7.0` is always present, the `@types/*` companion packages declared by TechSpecs are still merged in as before, and non-TypeScript targets are unaffected.
